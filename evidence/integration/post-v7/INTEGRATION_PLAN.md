# Full Post-V7 integration plan

## Exit predicate

The terminal predicate is exact canonical equality after safe promotion,
combined source and adversarial gates with owned Critical and High findings at
zero, an immutable release whose CURRENT/PREVIOUS and rollback identities
validate, healthy Supervisor/heartbeat/STOP/resume, truthful account and
procedure readiness, a bounded integrated live/disposable scenario with
`MANUAL_CONTINUATION_REQUIRED = 0`, and a final report that labels absent
credentials and unrun long profiles honestly.

## Ordered units

1. Freeze orientation and candidate provenance.
2. Integrate Lane 1 account activation and run its factory and focused tests.
3. Integrate Lane 2 procedure library and run catalog/validator/factory tests.
4. Integrate Lane 3 observer harness and run focused harness tests.
5. Wire account readiness to the capability broker and procedure eligibility.
6. Wire procedure selection through V7A to V7B, V5 effects, verifier, outcome,
   calibration, and maturity evidence.
7. Wire V7C incident containment and V6 evidence signals without creating a
   second authority.
8. Add the harness observer contract over canonical runtime events.
9. Run focused, affected, full, security, hygiene, migration, replay,
   reconcile, and adversarial gates. Repair only deterministic failures with
   a regression and fresh evidence.
10. Advance canonical main normally, build an exact immutable release, prove
    database backup/migration/rollback, and promote only after all gates pass.
11. Run account readiness, live safe procedure proof, bounded unattended proof,
    controlled restart, STOP/resume, and final adversarial checks.

## Invariants and boundaries

The Supervisor remains deterministic and independent of model/Hermes. STOP,
append-only truth, singleton leases, brokered capabilities, effect tickets,
idempotency, UNKNOWN after ambiguous effects, bounded repair, durable owner
directives, V4 exception management, V5 connectors/effects, V6 evidence, and
V7A/V7B/V7C authority remain canonical. The harness cannot authorize work.
Account content is DATA_ONLY. `PROVEN_ONCE` is not `TRUSTED`. No real account
or external write is attempted without explicit owner authorization. Voice and
localization remain separate final-polish readiness unless existing seams make
minimal safe integration possible.

## Verification cadence

Each unit ends with a focused check and an evidence checkpoint before the next
unit. The full Python suite runs once after source stabilization. Long profiles
remain `READY_NOT_RUN` unless a stable integrated runtime justifies launching
them. No full suite is rerun without an intervening source or release change.
