=== THE PRODUCT (fixed) ===
JARVIS is a command-line tool with an optional background service. It:
1. Accepts a coding task for a registered git repo, either from the CLI or from a GitHub issue labeled "jarvis".
2. Creates an isolated git worktree and branch for the task.
3. Runs a coding agent headlessly in that worktree. The agent gets the task, the repo's notes file and JARVIS's rules.
4. Verifies the result itself and never trusts the agent's claims. Specifically:
   - it runs the repo's own test and lint commands;
   - it checks that the diff is non-empty;
   - it checks that the diff stays inside the allowed scope.
5. On failure, retries with the failure output fed back to the agent, at most 2 repair attempts. After that it marks the task FAILED with a reason and keeps the branch for inspection.
6. On success, pushes the branch and opens a pull request. The PR body contains:
   - a summary;
   - the changed files;
   - the verification commands and their output;
   - the engine and model used;
   - cost and duration.
7. Never merges. Never pushes to the default branch. Never deploys.
8. STOP halts all work within seconds, including killing the agent subprocess. RESUME continues the queue.
9. Keeps a notes file per repo (commands, conventions, lessons). JARVIS proposes additions after tasks. The user accepts or rejects them.

Out of scope for the beta. Do not build these, and do not stub them:
- email, calendar, voice;
- chat integrations other than one generic webhook;
- desktop or Windows UI automation, browser automation, screen capture;
- office documents;
- a world model;
- autonomous goal invention, scheduled or nightly jobs, task proposals, multi-day campaigns;
- self-update or release-slot machinery, trust levels;
- a web dashboard, Obsidian integration, MCP servers of our own.
Good ideas in these areas go into a "Later" list in ARCHITECTURE.md (15 lines maximum), and nowhere else.

Coding engine: a pluggable AgentRunner interface. The engine and model come from config. Do not hard-pin any model. Check each engine CLI's current flags with --help; do not rely on memory. Ship these runners:
- claude_code (the default): Claude Code headless (claude -p with JSON output).
  - Use permission settings suitable for unattended work confined to the worktree.
  - Enforce a timeout.
  - Read cost from the reported usage when it is available.
- codex: Codex CLI (codex exec). Implement it. If you cannot install or authenticate it here, document it as NOT VERIFIED.
- hermes: optional. Port the subprocess call from src/jarvis_foundry/workers/adapters/hermes.py, without the spend gateway, model pinning or profile rewriting.
- fake: a deterministic scripted agent for tests.

Target layout. You may change names, but keep this shape:
  src/jarvis/cli.py           commands: init, repo add/ls, add, ls, show, run, serve, stop, resume, approve, notes
  src/jarvis/config.py        ~/.jarvis/config.toml, with a JARVIS_HOME override. Holds repos, engine, limits, webhook.
  src/jarvis/store.py         SQLite with plain tables: repos, tasks, runs, log. Simple migrations.
  src/jarvis/worktree.py      create and clean up one worktree and branch per task
  src/jarvis/agents/          base.py, claude_code.py, codex.py, hermes.py, fake.py
  src/jarvis/prompt.py        builds the prompt from the task, the repo notes and the rules
  src/jarvis/repo_profile.py  detects test, lint and build commands from manifests; config can override
  src/jarvis/verify.py        runs commands with timeouts, checks scope, produces a verdict
  src/jarvis/github.py        pushes and opens PRs via gh; reads labeled issues
                              also has a "local" mode (bare-repo remote plus a PR-body file) for tests
  src/jarvis/runner.py        the task lifecycle loop
  src/jarvis/stop.py          the STOP sentinel
  src/jarvis/notify.py        optional generic webhook

Phase 5: quality features
Add these in order:
1. Plan first for large tasks.
   - A config threshold decides which tasks count as large, and "jarvis add --plan" forces it.
   - JARVIS shows the plan and waits for "jarvis approve <id>".
2. Reviewer pass. A second agent call reviews the diff against the task and lists risks in the PR body. It informs; it does not gate.
3. Repo notes proposals. "jarvis notes <repo>" lists proposed lessons, with --accept and --reject.
4. GitHub label intake.
   - "jarvis serve" polls registered repos for issues labeled "jarvis".
   - The PR links to its issue.
   - On failure, JARVIS comments on the issue.
5. Time and cost caps per task. If an engine does not report cost, record "NOT REPORTED"; never guess.
6. Webhook notifications: "PR ready" and "failed, needs you".
7. "jarvis serve" as a background loop.
   - Configurable concurrency, default 1.
   - Graceful shutdown.
   - Runs from the installed package, never from a development checkout.
After this phase, re-run the full Phase 4 suite. It must not regress.

=== WORKING RULES ===
- Replace, don't layer. There is one implementation per job. When you rewrite something, delete the old version in the same commit.
- Use boring tools: git, gh, subprocess, sqlite3, tomllib, one CLI library, pytest and ruff. No orchestration frameworks, no event sourcing, no ORM.
- Every feature must be reachable from the CLI and covered by a test. No code that nothing calls.
- Tests never touch the real HOME, PATH, registry, credentials or real repositories. Use temp directories and JARVIS_HOME.
- Allowed docs: README, IDEA, ARCHITECTURE, AGENTS, BETA, CHANGELOG, plus the temporary RESET_STATUS.md. No report, evidence, handoff or checkpoint files.
- When a product detail is unclear, choose the simplest behavior consistent with THE PRODUCT. Add one line about the choice under "Decisions" in ARCHITECTURE.md, and continue.
- Ask the owner only when blocked by one of these:
  - missing credentials that a gate item needs;
  - an action outside AUTHORITY;
  - a contradiction inside this prompt.
  Ask once, precisely, and keep working on everything else in the meantime.
- If the same failure blocks you 3 times, stop and step back. Write the root cause in RESET_STATUS.md, then try a different approach or simplify.
